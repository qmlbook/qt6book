## 跟踪动态对象

使用动态对象时，经常需要跟踪已创建的对象。另一个常见需求是能够存储并恢复动态对象的状态。这两项任务都可以用一个动态填充的 `XmlListModel` 轻松处理。

在下面展示的例子中，可以创建火箭和 UFO 两种元素，并由用户移动它们。为了能够操纵由动态创建的元素组成的整个场景，我们用一个模型来跟踪这些项。

这个模型是一个 `XmlListModel`，它在项被创建时得到填充。对象引用与实例化时所用的源 URL 一起被跟踪。后者并非跟踪对象的严格需要，但稍后会派上用场。

从上面的例子可以看出，`create-object.js` 是前面介绍过的 JavaScript 的更一般化的形式。`create` 方法使用三个参数：源 URL、根元素，以及完成时要调用的回调。回调被调用时会收到两个参数：新创建对象的引用和所用的源 URL。

这意味着，每次调用 `addUfo` 或 `addRocket` 函数时，新对象创建完成后都会调用 `itemAdded` 函数。后者会把对象引用和源 URL 追加到 `objectsModel` 模型中。

`objectsModel` 有很多种用法。在当前这个例子中，`clearItems` 函数依赖于它。该函数演示了两件事。第一，如何遍历模型并执行一项任务，即对每个项调用 `destroy` 函数将其移除。第二，它揭示了这样一个事实：对象被销毁时，模型并不会随之更新。与该对象关联的模型项不会被移除，而是把该模型项的 `obj` 属性设为 `null`。为了弥补这一点，代码必须在对象被移除时显式地清除对应的模型项。

这个例子演示了如何用模型来跟踪已创建的项，以及对这类信息进行序列化和反序列化有多么容易。这可以用来存储动态填充的场景，例如一组小部件。在示例中，就用一个模型来跟踪每个项。

另一种解决方案是用场景根对象的 `children` 属性来跟踪项。不过，这要求项自身知道用于重新创建它们的源 URL。它还要求我们实现一种方式，能够把动态创建的项与原始场景中就存在的项区分开来，从而避免试图序列化任何原始项，并在之后将其反序列化。
