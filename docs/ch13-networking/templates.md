# 模板

在 HTML 项目中，开发常常采用模板驱动的方式：一小段 HTML 桩代码会在服务器端用模板机制生成的代码展开。例如，对于照片列表，列表的页眉会用 HTML 编写，而动态的图像列表则通过模板机制动态生成。一般来说，用 QML 也能做到同样的事，但存在一些问题。

首先，这没有必要。HTML 开发者这样做，是为了绕过 HTML 后端的局限。HTML 至今没有组件模型，因此动态部分只能依靠这些机制，或者在客户端用 JavaScript 以编程方式处理。有许多 JS 框架（jQuery、dojo、backbone、angular……）专门解决这个问题，把更多逻辑放进客户端浏览器，以便与网络服务连接。客户端随后只需使用 Web 服务 API（例如提供 JSON 或 XML 数据）与服务器通信。对 QML 而言，这似乎也是更好的方法。

第二个问题是 QML 的组件缓存。QML 访问一个组件时，会缓存其渲染树（render-tree），之后只加载缓存的版本进行渲染。磁盘或远程位置上修改过的版本不会被检测到，除非重启客户端。为了解决这个问题，我们可以用一个小技巧：使用 URL 片段（fragment）来加载 URL（例如 [http://localhost:8080/main.qml#1234](http://localhost:8080/main.qml#1234)），其中 ‘#1234’ 就是片段。HTTP 服务器总是提供同一份文档，但 QML 会用包含片段的完整 URL 来保存这份文档。每次访问该 URL 时都更换片段，QML 缓存就不会命中。片段可以是当前时间的毫秒数，也可以是随机数。

```qml
Loader {
    source: 'http://localhost:8080/main.qml#' + new Date().getTime()
}
```

总之，模板技术是可行的，但并不推荐，它也发挥不了 QML 的长处。更好的做法是使用提供 JSON 或 XML 数据的 Web 服务。
